# ISLAND MYSTERY
## DEVELOPMENT PHASE 7 — REAL-TIME ONLINE MULTIPLAYER
### 실시간 멀티플레이 · 게임방 생성 · 친구 초대 · AI 혼합 플레이 · 서버 동기화 · 온라인 심리전

당신은 ISLAND MYSTERY 프로젝트의 수석 멀티플레이 게임 개발자, 네트워크 프로그래머, 백엔드 아키텍트, 보안 엔지니어 및 QA 엔지니어입니다.

지금부터 PHASE 1~6에서 개발한 기존 ISLAND MYSTERY를 기반으로 온라인 멀티플레이 시스템을 개발합니다.

이번 단계의 최종 목표는 **실제 사람 2~6명이 인터넷을 통해 같은 게임방에 접속하여 함께 섬을 탐험하고, 토론하고, 투표하고, 공작원을 찾아내는 온라인 게임을 구현하는 것**입니다.

부족한 인원은 AI 캐릭터가 자동으로 채웁니다.

기존 싱글플레이 기능은 그대로 유지합니다.

단순한 멀티플레이 UI 시연이나 가짜 연결 상태 표시가 아니라 실제 네트워크를 통한 게임 상태 동기화가 이루어져야 합니다.

온라인 멀티플레이에서는 중앙 서버가 게임 진행을 관리하도록 구현합니다.

권장 기술:

프런트엔드:
- 기존 HTML5
- CSS3
- JavaScript

백엔드:
- Node.js
- Socket.IO
- 필요 시 Express

실시간 통신:
- WebSocket 기반 통신
- Socket.IO를 통한 연결 및 재연결 관리

기존 게임 엔진과 규칙을 가능한 한 재사용하세요.

온라인 게임에서는 서버가 최종 게임 상태와 승패를 결정해야 합니다.

클라이언트는 사용자의 행동 요청을 서버로 전달하고, 서버가 유효성을 검사한 후 처리 결과를 전송하는 구조로 만듭니다.

다음 정보는 서버에서 관리합니다.

- 플레이어 직업
- 공작원 정체
- 비밀 목표
- 비공개 행동
- AI 내부 기억
- 투표 전 비공개 선택
- 전체 게임 상태
- 자원 및 시설 상태
- 승패 판정

중요:

**클라이언트의 화면을 수정하거나 개발자 도구를 사용해도 다른 사람의 비밀 직업이나 공작원 정보를 얻을 수 없도록 설계하세요.**

서버는 각 플레이어에게 공개 가능한 정보만 전송해야 합니다.

기존 싱글플레이 저장 방식과 온라인 서버의 데이터 관리 방식을 구분합니다.

"현재 온라인 서버에 연결할 수 없습니다. 싱글플레이는 계속 이용할 수 있습니다."

온라인 연결 실패로 기존 싱글플레이 기능이 중단되지 않도록 하세요.

# PART 4. 게임방 생성 시스템

## STEP 4 — 온라인 게임방 만들기

플레이어가 직접 게임방을 생성할 수 있도록 합니다.

게임방 생성 시 다음 항목을 설정합니다.

- 게임방 이름
- 플레이어 닉네임
- 공개방 또는 비공개방
- 게임 난이도
- AI 플레이어 허용
- 토론 제한 시간
- 게임방 최대 인원

최대 게임 참여 인원은 총 6명입니다.

사람이 2명 참여하면 AI 4명이 추가됩니다.

사람이 3명 참여하면 AI 3명이 추가됩니다.

사람이 4명 참여하면 AI 2명이 추가됩니다.

사람이 5명 참여하면 AI 1명이 추가됩니다.

사람이 6명 참여하면 AI 없이 진행합니다.

기존의 인간 1명과 AI 5명 플레이는 싱글플레이 모드에서 지원합니다.

게임방을 만들면 고유한 방 코드를 생성합니다.

예시:

ISLAND-7K2M

방 코드는 충돌 가능성을 충분히 낮추도록 안전하게 생성합니다.

게임방에는 다음 정보가 표시되어야 합니다.

- 방 이름
- 방 코드
- 방장 닉네임
- 현재 참가 인원
- AI 인원
- 게임 난이도
- 참가자 준비 상태
- 게임 시작 버튼

방장만 게임을 시작할 수 있도록 합니다.

최소 2명의 실제 플레이어가 접속하고 준비해야 온라인 게임 시작이 가능합니다.

# PART 5. 친구 초대 및 참가

## STEP 5 — 초대 시스템

친구 초대 방식은 두 가지로 구현합니다.

### 방식 A — 방 코드 참가

방장이 방 코드를 친구에게 전달합니다.

친구는 게임방 참가 화면에서 방 코드를 입력하여 입장합니다.

### 방식 B — 초대 링크

방장이 초대 링크를 복사할 수 있습니다.

친구는 링크를 통해 게임방 참가 화면으로 이동합니다.

실제 서버 주소가 설정된 경우 정상적으로 연결되는 초대 링크를 생성하세요.

아직 공개 서버가 없다면 로컬 개발 환경에서만 작동하는 링크와 공개 인터넷용 링크를 구분하여 안내하세요.

허위로 공개 서버가 운영되고 있다고 표시하지 마세요.

비공개방은 유효한 초대 코드 또는 허용된 초대 절차를 거쳐야 입장할 수 있어야 합니다.

방이 가득 찼거나 이미 시작되었으면 적절한 안내를 표시합니다.

# PART 6. 게임 대기실

## STEP 6 — 멀티플레이 로비

게임을 시작하기 전에 모든 플레이어가 모이는 대기실을 구현합니다.

대기실 기능:

- 참가자 닉네임 표시
- 현재 접속 상태
- 준비 완료 버튼
- 준비 취소 버튼
- 방 코드 복사
- 초대 링크 복사
- AI 인원 표시
- 게임 난이도 표시
- 방 나가기
- 게임 시작

참가자가 나가면 실시간으로 인원 목록을 갱신합니다.

방장이 나가면 다른 실제 참가자에게 방장 권한을 이전합니다.

방장이 게임을 시작하면 모든 참가자의 화면이 동시에 게임 화면으로 전환되어야 합니다.

중복 클릭으로 같은 게임이 두 번 시작되지 않도록 처리합니다.

게임 시작 후 새로운 일반 참가자가 중간에 입장해 기존 플레이어의 역할을 빼앗을 수 없어야 합니다.

# PART 7. 온라인 직업 배정

## STEP 7 — 서버 기반 비밀 직업 시스템

게임 시작 시 서버가 6명의 직업을 배정합니다.

직업 구성:

- 탐험가
- 의사
- 기술자
- 조사관
- 공작원

공작원은 정확히 1명입니다.

나머지 5명에게 생존자 직업 4종류를 배정하며 하나의 직업은 중복됩니다.

직업 배정은 서버에서 무작위로 처리합니다.

플레이어는 자신의 직업만 확인할 수 있습니다.

다른 플레이어의 직업은 비밀로 유지합니다.

게임 시작 시 각 참가자에게 개별 직업 안내 화면을 제공합니다.

예시:

"당신은 조사관입니다."

"밤에 다른 생존자를 조사하여 단서를 얻을 수 있습니다."

공작원으로 배정된 플레이어에게는 다음과 같이 안내합니다.

"당신은 공작원입니다."

"다른 생존자들이 탈출하지 못하도록 방해하면서 정체를 숨기세요."

비밀 정보는 해당 플레이어에게만 전송합니다.

게임 종료 후에는 최종 결과 화면에서 직업을 공개할 수 있습니다.

# PART 8. 실시간 게임 진행 동기화

## STEP 8 — 모든 참가자의 게임 상태 동기화

게임은 최대 3일 동안 진행됩니다.

기존 진행 순서를 유지합니다.

1. 아침 — 탐험
2. 낮 — 비밀 임무
3. 저녁 — 토론
4. 투표
5. 밤 — 특수능력
6. 다음 날

각 단계는 서버가 관리합니다.

플레이어마다 서로 다른 날짜나 단계가 표시되는 오류가 없어야 합니다.

모든 참가자가 행동을 완료하면 다음 단계로 이동합니다.

단계별 제한 시간이 있는 경우 제한 시간 이후에는 미완료 행동을 게임 규칙에 따라 자동 처리합니다.

행동 중복 요청, 잘못된 단계의 요청, 추방된 플레이어의 요청은 서버에서 거부해야 합니다.

화면 전환 애니메이션 때문에 실제 게임 상태가 중복 변경되어서는 안 됩니다.

# PART 9. 온라인 탐험 시스템

## STEP 9 — 멀티플레이 탐험

모든 참가자가 탐험 지역을 선택할 수 있도록 구현합니다.

기존 네 지역을 유지합니다.

- 해안가
- 정글
- 연구소
- 통신탑

온라인 탐험에서는 다음 기능을 지원합니다.

1. 개인별 지역 선택
2. 지역별 탐험 결과 계산
3. 자원 획득
4. 단서 발견
5. 부상
6. 사건 발생
7. 탐험 결과 공개 범위 처리
8. 모든 참가자의 탐험 완료 확인

탐험 결과는 서버가 계산합니다.

게임 규칙상 공개 가능한 탐험 결과는 모든 참가자에게 공유합니다.

개인 단서는 해당 플레이어에게만 전달합니다.

AI 플레이어도 같은 규칙으로 탐험에 참여합니다.

서버가 자원 합산을 한 번만 수행하도록 하세요.

# PART 10. 실시간 채팅과 토론

## STEP 10 — 플레이어 간 실시간 대화

이번 PHASE 7의 핵심 기능입니다.

저녁 토론 단계에서 실제 사람들이 서로 대화할 수 있도록 구현합니다.

우선 텍스트 채팅을 구현합니다.

기본 기능:

- 실시간 메시지 전송
- 닉네임 표시
- 메시지 순서 유지
- 채팅 기록
- 시스템 메시지
- AI 캐릭터의 토론 참여
- 토론 제한 시간
- 대화 스크롤

AI 캐릭터는 PHASE 3에서 구현한 기억과 신뢰 시스템을 사용하여 실제 인간 플레이어의 공개 행동과 발언을 참고해야 합니다.

다만 자유 입력 채팅의 의미를 완벽하게 이해하는 AI를 이번 단계에서 반드시 구현할 필요는 없습니다.

AI는 구조화된 행동, 증거 공개, 선택형 발언을 우선적으로 판단하도록 합니다.

실제 사람의 자유 채팅을 AI가 이해했다고 허위로 표시하지 마세요.

채팅 시스템에는 기본적인 입력 길이 제한, 메시지 전송 속도 제한, 위험한 HTML 실행 방지 및 신고·차단을 위한 확장 구조를 마련합니다.

# PART 11. 온라인 투표 시스템

## STEP 11 — 실시간 비밀 투표

토론이 종료되면 투표 단계로 이동합니다.

투표 조건:

- 살아 있는 참가자만 투표 가능
- 자기 자신에게 투표 불가
- 플레이어당 1회 확정
- AI도 자동 투표
- 투표 완료 여부 표시
- 모든 투표 완료 후 결과 발표
- 제한 시간 만료 시 미투표 자동 처리

투표 결과가 공개되기 전까지 다른 사람의 투표 대상은 비밀로 유지합니다.

투표 집계는 반드시 서버에서 처리합니다.

최다 득표자가 1명이면 추방합니다.

동률이면 아무도 추방하지 않습니다.

투표 결과가 발표되면 모든 참가자에게 동일한 결과가 표시되어야 합니다.

한 참가자가 새로고침하거나 연결을 끊어도 투표가 중복 집계되지 않도록 합니다.

# PART 12. 비밀 밤 행동

## STEP 12 — 직업별 온라인 특수능력

밤에는 직업별 능력을 사용할 수 있습니다.

- 의사: 치료 또는 보호
- 기술자: 시설 보수
- 조사관: 조사
- 탐험가: 제한된 정찰
- 공작원: 시설 파괴 및 방해

밤 행동은 서버에서 처리합니다.

공작원의 행동 대상과 결과는 규칙상 공개 가능한 상황이 되기 전까지 다른 플레이어에게 노출하지 않습니다.

조사관의 개인 조사 결과는 해당 조사관에게만 전달합니다.

각 플레이어의 밤 행동이 완료되면 서버가 정해진 순서로 행동을 해결합니다.

사망 또는 추방된 플레이어의 밤 행동은 실행되지 않아야 합니다.

AI와 인간 플레이어가 동일한 행동 처리 규칙을 사용하도록 하세요.

---

# PART 13. AI 혼합 플레이

## STEP 13 — 인간과 AI가 함께 참여하는 게임

ISLAND MYSTERY의 중요한 차별화 요소입니다.

온라인 참가자가 6명 미만이면 AI가 부족한 자리를 채웁니다.

AI는 다음 게임 규칙을 인간 플레이어와 동일하게 따라야 합니다.

- 직업 배정
- 탐험
- 자원 관리
- 토론
- 의심 및 신뢰
- 투표
- 밤 행동
- 승패 판정

AI가 공작원이 될 수도 있습니다.

인간 플레이어가 공작원이 될 수도 있습니다.

AI가 인간 플레이어의 비밀 직업을 미리 알고 행동하지 않도록 합니다.

AI는 서버에서 실행되는 기존 의사결정 엔진을 사용합니다.

AI 행동 때문에 게임 진행이 무한정 지연되지 않도록 시간 제한 및 예외 처리 기능을 구현합니다.

이번 단계에서는 중간 이탈자를 AI로 즉시 교체하는 기능을 필수로 구현하지 않아도 됩니다.

우선은 중간 이탈과 재접속을 안정적으로 처리하는 데 집중합니다.

---

# PART 14. 연결 끊김 및 재접속

## STEP 14 — 재접속 시스템

온라인 게임에서는 연결이 끊기는 상황이 발생할 수 있습니다.

다음 상황에 대응하세요.

1. 브라우저 새로고침
2. 일시적인 인터넷 연결 끊김
3. 브라우저 창 닫기
4. 참가자 중도 이탈
5. 방장 연결 끊김
6. 서버 연결 오류

플레이어가 잠시 연결이 끊겼다가 돌아오면 기존 게임에 복귀할 수 있어야 합니다.

복귀할 때 동일한 캐릭터와 직업을 유지합니다.

임의의 닉네임만 입력해서 다른 플레이어의 자리를 빼앗을 수 없어야 합니다.

재접속 전용 보안 토큰을 사용하고 서버에서 유효성을 검사하세요.

토큰은 임의로 추측하기 어렵게 생성합니다.

토큰이나 비밀 정보가 공개 채팅 또는 개발 로그에 출력되지 않도록 합니다.

연결이 끊어진 동안 게임이 무한정 멈추지 않도록 단계별 시간 제한과 기본 행동 처리 규칙을 구현합니다.

# PART 15. 관전 및 게임 종료

## STEP 15 — 추방 이후 관전 모드

인간 플레이어가 추방되면 관전 모드로 전환합니다.

관전자는 게임이 끝날 때까지 진행 상황을 볼 수 있습니다.

단, 게임 종료 전에는 다른 참가자들의 비밀 정보가 노출되지 않도록 합니다.

관전 중에는 다음 행동을 할 수 없습니다.

- 탐험
- 임무 수행
- 투표
- 밤 능력 사용
- 생존자 토론에 참여

게임 종료 후 모든 참가자가 같은 승패 결과를 확인하도록 합니다.

결과 화면에는 다음 정보를 표시합니다.

- 승리 진영
- 공작원의 정체
- 생존자 목록
- 추방된 캐릭터
- 주요 사건
- 게임 진행 날짜
- 주요 단서
- 개인 비밀 목표 결과

게임 종료 후 방장에게 재대결 기능을 제공합니다.

재대결 시 직업과 비밀 목표를 새로 배정합니다.

# PART 16. 서버 보안 및 치트 방지

## STEP 16 — 온라인 게임 보안

다음 원칙을 반드시 적용합니다.

1. 클라이언트가 승패를 직접 결정하지 못하도록 합니다.
2. 클라이언트가 자원을 임의로 증가시키지 못하도록 합니다.
3. 다른 플레이어의 비밀 직업을 클라이언트에 전송하지 않습니다.
4. 모든 행동 요청은 서버에서 검사합니다.
5. 투표는 서버에서 중복 집계를 방지합니다.
6. 방 코드와 재접속 토큰은 안전하게 생성합니다.
7. 비정상적인 메시지 전송을 제한합니다.
8. 허용되지 않은 게임방 접근을 차단합니다.
9. 입력값을 검증하고 화면 출력 시 안전하게 처리합니다.
10. 공개 운영 시 HTTPS 및 보안 WebSocket 연결을 사용합니다.

게임 상태를 서버 전체 데이터 그대로 전송한 후 화면에서 숨기는 방식은 사용하지 마세요.

각 플레이어에게 필요한 정보만 전달하는 별도의 응답 구조를 구현하세요.

서버를 재시작했을 때 게임방이 유지되는지 여부도 명확히 설계하고 문서에 기록하세요.
