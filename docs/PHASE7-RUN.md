# Phase 7 · Windows 실행 설명서

## 1. 필요한 프로그램과 설치

Windows용 Node.js **22 이상**과 최신 Chrome 또는 Firefox가 필요합니다. [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 Windows 설치 프로그램을 받아 설치하세요. 설치 후 새 터미널에서 `node --version`을 실행하면 버전이 표시됩니다.

GitHub 저장소의 파일을 한 폴더에 내려받으세요. `index.html`, `package.json`, `server`, `js`, `assets`, `start-online.cmd`가 같은 프로젝트 폴더에 있어야 합니다. 최초 패키지 설치 때 인터넷이 필요하며 이후 로컬 게임 자체는 외부 AI API를 사용하지 않습니다.

## 2. 서버 실행

`start-online.cmd`를 더블클릭하세요. 필요한 패키지가 없으면 `npm ci`로 설치한 뒤 서버를 실행합니다. 터미널 창을 닫지 마세요. 기본 주소는 `http://127.0.0.1:4174`입니다. `.env`에서 포트를 바꿨으면 서버가 마지막으로 출력하는 주소를 사용하세요.

직접 실행할 때는 프로젝트 폴더에서 다음을 입력합니다.

```powershell
npm ci
npm start
```

설정을 바꾸려면 `.env.example`을 `.env`로 복사해 편집하고 서버를 다시 시작합니다. 더블클릭 스크립트는 `.env`를 자동으로 읽습니다. 직접 실행할 때는 `node --env-file=.env server/index.cjs`를 사용하세요. `npm start`는 환경 변수를 읽지만 `.env` 파일을 자동으로 불러오지는 않습니다.

## 3. 게임 접속과 방 생성

브라우저에서 출력된 주소를 여세요. **온라인 멀티플레이**를 누르면 서버 연결 상태가 표시됩니다. 닉네임, 방 이름, 공개 여부, 난이도, 최대 실제 참가 인원, AI 허용, 토론 시간을 정하고 **방 만들기**를 누릅니다. 실제 참가자는 2~6명이며 빈 좌석은 AI가 채웁니다. AI를 끈 방은 실제 참가자 6명이 필요합니다.

공개방은 목록에 표시됩니다. 비공개방은 방 코드로만 들어갈 수 있으므로 코드를 초대할 사람에게만 공유하세요. 시작한 방에는 새 참가자가 들어갈 수 없습니다.

## 4. 친구 참가와 초대

같은 PC에서는 Chrome와 Firefox, 또는 일반 창과 시크릿 창을 사용하세요. 같은 브라우저의 일반 탭은 재접속 정보를 공유하므로 서로 다른 참가자 테스트에는 독립된 프로필/시크릿 창이 필요합니다.

방 코드 또는 초대 링크를 복사해 전달하세요. 링크를 열면 코드가 입력된 참가 화면이 나오고 친구가 닉네임을 정해 입장합니다. 모두 **준비 완료**를 누른 뒤 방장이 시작합니다. 각자 자신의 비밀 직업 안내를 확인하세요. 캐릭터 카드에는 닉네임을 함께 표시하고 본인에게만 **나** 배지가 붙습니다.

`127.0.0.1`과 `localhost`는 **주소를 여는 기기 자신**을 가리킵니다. 이 주소를 다른 기기로 보내도 같은 서버에 연결되지 않습니다.

같은 신뢰할 수 있는 LAN의 다른 기기에서 접속하려면 다음을 설정하세요.

1. `.env`에서 `HOST=0.0.0.0`, `PORT=4174`, `NODE_ENV=development`로 설정합니다.
2. 서버 PC에서 `ipconfig`로 현재 LAN IPv4 주소를 확인합니다.
3. Windows 방화벽에서 해당 사설 네트워크의 TCP 4174 접속만 허용합니다.
4. 서버 PC와 친구 모두 `http://서버의-LAN-IP:4174`로 접속합니다. 이 주소로 만든 초대 링크를 공유합니다.

개발용 HTTP는 신뢰할 수 있는 로컬 환경에만 사용하세요. 같은 Wi-Fi라도 게스트 네트워크의 기기 간 차단이 있으면 연결되지 않습니다. LAN 안내는 제공하지만 이번 검증은 한 PC의 독립 브라우저로 수행했으며 두 물리 기기 테스트는 수행하지 않았습니다.

## 5. 플레이와 복귀

각 단계에서 한 행동을 확정합니다. 서버가 활동 중인 인간 전원의 제출을 기다린 뒤 AI와 함께 좌석 순서로 실행합니다. 먼저 실행된 행동 때문에 공동 물자가 부족해지면 뒤의 행동은 휴식 등 기본 행동으로 바뀌고 개인 기록에 표시됩니다.

기본 행동 시간은 60초, 사건 선택은 30초, 결과 표시는 2.5초입니다. 토론은 설정한 전체 시간을 5개 소단계에 균등 배분합니다. 자유 채팅은 토론 중에 사용하며 AI는 선택형 발언·공개 증거를 읽습니다. 모두 행동을 제출하면 남은 시간이 있어도 해당 소단계가 끝납니다.

투표 후보와 확인 버튼으로 확정하며 다른 사람의 표는 집계 전까지 비공개입니다. 사망·추방되면 관전하고 생존자 채팅과 행동에 참여할 수 없습니다. 밤 정산과 날짜 변경은 자동입니다. 종료 후 **현재 방장**이 재대결을 준비하면 모두 다시 준비해야 합니다.

새로고침하거나 일시적으로 연결이 끊겨도 같은 브라우저 저장소의 토큰으로 복귀합니다. 방장이 끊기면 접속한 다음 참가자에게 권한이 넘어가며 복귀했다고 자동으로 돌려받지는 않습니다. 끊긴 동안 게임은 제한 시간에 따라 계속 진행됩니다. 토큰을 지우거나 **방 나가기**를 확정하면 기존 좌석을 되찾을 수 없습니다.

## 6. 서버 종료와 저장

서버 터미널에서 **Ctrl+C**를 누릅니다. 배치 종료 확인이 나오면 종료를 선택하세요. **온라인 방·채팅·진행·재접속 정보는 서버 재시작 후 복원되지 않습니다.** 접속자가 없는 방은 기본 10분 뒤 정리됩니다.

싱글플레이는 기존 localStorage 저장을 사용합니다. 파일 주소, 4173, 4174, LAN 주소는 브라우저 저장 영역이 서로 다르므로 같은 주소로 접속해야 같은 저장을 볼 수 있습니다. 온라인 서버 연결이 실패해도 싱글플레이 버튼으로 돌아갈 수 있습니다.

## 7. 자주 발생하는 오류

| 증상 | 해결 방법 |
| --- | --- |
| `node`를 찾을 수 없음 | Node.js 22 이상 설치 후 터미널을 새로 열기 |
| 패키지 설치 실패 | 인터넷 연결을 확인하고 프로젝트 폴더에서 `npm ci` 실행 |
| `EADDRINUSE` | 같은 포트의 기존 서버를 종료하거나 `.env`의 PORT 변경 |
| 온라인 서버 연결 불가 | 서버 창을 유지하고 HTTP 주소로 접속. HTML 파일 더블클릭은 싱글플레이용 |
| 시작 버튼 비활성화 | 최소 2명 전원 연결·준비 확인. AI 비허용이면 6명 필요 |
| 재대결 버튼 없음 | 방장 위임 여부 확인. 현재 방장에게만 표시 |
| 다른 탭에서 튕김 | 같은 토큰으로 재접속한 것. 서로 다른 참가자는 독립 브라우저 저장소 사용 |
| 복귀 인증 실패 | 서버가 재시작됐거나 토큰이 삭제/취소됨. 새 방에 참가 |
| 링크로 다른 기기 접속 불가 | localhost 대신 서버 LAN 주소 사용. 방화벽/네트워크 격리 확인 |
| 복사 버튼이 작동하지 않음 | 주소 입력란을 직접 복사. HTTP LAN에서는 브라우저 클립보드 권한이 제한될 수 있음 |
| 행동이 이미 확정됨 | 중복 방지에 따른 정상 응답. 서버의 다음 단계까지 기다리기 |

## 8. 인터넷 공개 서버 준비

이번 단계는 로컬 서버 검증까지입니다. 공개 운영을 하려면 지속 실행 가능한 Node.js 호스트, HTTPS 인증서, WebSocket Upgrade를 지원하는 역방향 프록시, 운영 로그·재시작 관리가 필요합니다. 현재 방 저장은 단일 프로세스 메모리이므로 다중 서버로 단순 복제할 수 없습니다. 확장 전 공유 상태 저장과 Socket.IO 어댑터/연결 라우팅을 설계해야 합니다.

운영 변수는 `.env.example`을 참고하세요. `NODE_ENV=production`에서 `APP_ORIGIN` 또는 `APP_DOMAIN`이 없으면 서버가 실패합니다. `APP_ORIGIN`은 경로와 마지막 슬래시가 없는 HTTPS 원점이며 우선 적용됩니다. `APP_DOMAIN`만 있으면 HTTPS 원점을 중앙 설정에서 구성합니다. 고정 도메인을 소스에 넣지 마세요. 원점과 실제 브라우저 주소가 일치해야 연결됩니다. 포워딩 헤더를 무조건 신뢰하지 않으므로 프록시 뒤 IP 제한은 여러 이용자가 공유할 수 있습니다. 실제 배포에서 프록시 수준의 접속 제한도 구성하세요.

DNS·인증서·운영 라우팅은 이번 작업에서 변경하지 않았습니다. 공개 접속, TLS 프록시, 두 기기, 지연/패킷 손실 및 장시간 부하 검증을 마친 뒤 운영하세요.

## 9. 검증 명령

```powershell
npm test
npm run test:online
# 서버를 별도 창에서 실행한 상태:
npm run test:browser:online
npm run test:browser:online-features
npm run test:browser:offline-regression
```

브라우저 검증에는 Playwright 브라우저가 필요합니다. `npx playwright install chrome firefox`로 설치할 수 있습니다. 온라인 완주 테스트는 Chrome와 Firefox의 실제 UI를 조작하며 결과를 `docs/phase7-browser-results.json`에 기록합니다. 오프라인 회귀에는 자연 완주와 조건부 저장 기반 시나리오가 함께 들어 있습니다.
