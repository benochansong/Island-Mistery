## 3. 개선된 주요 게임 화면

- 타이틀: 열대 섬·난파선·정글·연구소·통신탑이 있는 일러스트와 실제 메뉴. 저장이 없는 경우 이어하기 비활성화.
- 게임: 날짜·단계·자원, 지역 장면, 생존자 패널, 지도, 실행 버튼. 긴 화면에서는 **현재 행동으로** 링크로 이동할 수 있습니다.
- 지도: 선택한 지역 강조·도움말, 미발견 장소는 `? / 미발견`, 개방 후 이름·선택, 탐험 후 체크 표시. 도감에서도 미발견 장소 이름을 미리 공개하지 않습니다.
- 토론: 확정된 공개 발언을 초상화와 함께 재생하고, 사용자의 실제 선택지는 기존 행동 영역에서 제공합니다. 대화 기록 재생과 게임 진행을 분리했습니다.
- 사건: 36개 사건 각각의 설명, 장소, 공개 범위, 비용을 검사한 선택지와 처리 결과.
- 엔딩: 기존 승패·세부 결말·도감 저장을 유지하고 배경과 등장 효과·진영별 음악을 연결했습니다.

사용자 첫 입력 뒤 시작하며 음악 전환은 700ms 페이드입니다. 같은 효과음은 180ms 이내 반복을 막고 동시 효과음은 최대 3개, 전환 중 음악은 최대 2개로 제한합니다. 숨김 상태에서는 음악·효과음·자동 대사·패럴랙스 작업을 중단합니다. 음악 재생은 로컬 파일과 HTMLAudioElement를 사용하며 인터넷 서비스가 필요하지 않습니다.

## 7. 애니메이션 및 UI 개선 내용

렌더러에는 `viewFor`의 허용된 뷰만 전달합니다. 자원 증감은 전후 값의 차이, 발견은 신규 보유 단서, 표정은 공개 발언·체력·내 의심을 읽습니다. 다른 인물의 비밀 직업·목표·감정은 읽지 않습니다. 표정은 상황 표현이며 정체를 드러내는 증거가 아닙니다.

CSS로 등장·탐색·지도 잠금 해제·부상·발견·추방·엔딩을 표현하고 문자 표시·페이드·포인터 이동은 requestAnimationFrame을 사용합니다. 폭풍/전기/신호/문서/증언/물자 효과를 재사용합니다. 화면 흔들림은 기본으로 꺼져 있습니다. 효과 감소 설정과 OS 설정에서는 모션 없이 동일한 게임을 진행합니다.

사건 선택·투표는 기존 엔진이 먼저 처리합니다. 연출은 결과를 다시 굴리거나 투표를 재집계해 게임 상태에 쓰지 않습니다. 대사 재생의 이전/다음·즉시 표시·자동 재생도 저장된 게임 상태를 바꾸지 않습니다. 실제 토론을 넘기는 기존 버튼은 인간의 판단 유보와 AI 토론을 수행하는 별도 행동으로 유지합니다.

설정 키는 `island-mystery.settings.v1`이며 진행 `save.v4`, 도감 `codex.v1`과 분리합니다. 이미지 경로는 중앙 목록에서 가져와 문서 기준 URL로 해석합니다. 그림 실패 시 이니셜/기본 지도, 음원 실패 시 무음으로 동작하고 상태를 안내합니다.

## 8. 브라우저 실행 테스트 결과

검증 환경: Windows, Node.js 24.14.0, Playwright 1.65.1, Chrome 157.0.8103.79, Playwright Firefox 159.0. 실제 브라우저를 격리된 headless 컨텍스트로 실행했습니다. 사용자 브라우저 프로필은 사용하지 않았습니다.

**Chrome 전체 게임 3/3 완주:** 시드 1(의사, 30회 UI 진행), 2(의사, 25회), 5(공작원, 14회). 화면의 버튼과 선택지를 조작했고 게임 상태를 주입해 엔딩을 만들지 않았습니다. 아침·낮·토론·투표·밤의 화면과 음악, 사건 대기 중 새로고침·이어하기, 투표 취소/확정, 효과 감소 상태 완주, 엔딩, 도감 3회 누적을 확인했습니다. 최종 페이지/콘솔 오류 및 실제 실패 요청은 0건입니다. 음악을 전환하거나 페이지를 떠날 때 의도적으로 취소된 `ERR_ABORTED` 요청은 실패 집계에서 제외합니다.

**Chrome·Firefox 주요 기능 검사:** 양쪽 모두 9개 음악이 실제 재생 상태이며 재생 시간이 증가하고 페이드 후 목표 볼륨에 도달하는 것을 검사했습니다(총 18개 트랙 검사). 음악/효과음 끄기, 동일 효과음 중복 제한, 설정 저장·초기화, 전체화면, 네 지역 클릭, 미발견 장소 숨김, 효과 감소, 연출 50회 건너뛰기의 게임 저장 불변, 390px 화면에서 가로 넘침 없음이 통과했습니다. 숨김 상태 처리는 visibilitychange 조건을 만든 검사이며 실제 노트북의 절전·백그라운드 탭 장시간 동작 시험은 아닙니다.

**장애 조건:** 이미지·모든 음원 요청을 차단하고 저장 쓰기를 거부해도 탐험이 진행되고 오류 안내·이니셜·기본 지도·무음으로 대체됩니다. 전체화면 API 미지원도 일반 화면으로 계속합니다. 이 테스트의 의도적인 요청 차단은 정상 실행의 네트워크 오류와 별도입니다.

**별도 조건부 화면 검사:** 기존 엔진이 만든 서윤 5표 추방 결과를 렌더링해 최다 득표 강조와 비활성 초상화를 확인했습니다. 공개 대사 2개의 자동 재생·이전 발언·즉시 표시를 검사했고 실제 게임 저장은 변경되지 않았습니다. 이 조건 자료 검사를 전체 게임 완주 횟수에 포함하지 않습니다.

실측 원본: [전체 UI 결과](phase5-browser-results.json), [두 브라우저·오디오·장애 검사](phase5-browser-features.json), [조건부 화면 검사](phase5-scene-results.json). 화면 캡처를 직접 열어 타이틀·대화·사건·설정·밤의 텍스트와 버튼 배치를 확인했습니다.

개발 중 발견한 지역 선택자와 body 속성 이름 충돌, CSS 이미지 상대 경로 오류, RAF 시각 차이에 따른 음수 페이드 볼륨을 수정했습니다. Firefox에서는 효과 감소 여부를 최신 매체 쿼리로 읽도록 보완했습니다. 실패했던 중간 실행을 최종 통과로 집계하지 않았습니다.

## 10. 남아 있는 오류 및 미완성 사항

- 검사한 흐름에서 미해결 진행 오류는 없습니다. 모든 환경과 모든 사용자 행동 조합을 검증한 것은 아닙니다.
- 음악은 짧은 합성 앰비언트 루프입니다. 장편 스코어·자연 현장 녹음·성우 음성·전문 마스터링은 제작하지 않았습니다. 실제 오디오 디바이스 출력과 주관적 음질을 사람처럼 청음했다고 주장하지 않습니다.
- 캐릭터는 2D 초상화와 표정/조명 모션입니다. 립싱크·전신 애니메이션·3D는 없습니다. 같은 배경의 구도·색감 변형을 사용하며 지역별 독립 일러스트 4장을 제작한 것은 아닙니다.
- Safari·실제 iOS/Android·저사양 기기의 장시간 성능·스크린리더 전수 검증은 수행하지 않았습니다. 모바일 검사는 두 데스크톱 브라우저의 390px 뷰포트입니다. 장시간 메모리 프로파일링과 FPS 보장은 없습니다.
- Phase 4의 생존자 편향과 희귀 사건 노출 빈도는 유지됩니다. 이번 100회에서도 생존자 승률 96%이며 Phase 5에서 밸런스를 바꾸지 않았습니다.
- 여러 탭의 동시 저장 충돌은 기존처럼 지원하지 않습니다. 설정과 게임 저장 키의 충돌은 분리했으나 다중 탭 동기화를 새로 구현하지 않았습니다.

## 11. 사용자가 직접 확인해야 할 항목

1. `npm run dev`로 실행한 뒤 첫 클릭으로 소리를 시작하고, 스피커/헤드폰에서 음악과 효과음의 음량·음색·반복 피로도를 확인하세요.
2. 설정에서 음악/효과음·볼륨·효과 감소·문자 속도를 바꾸고 새로고침 후 유지되는지 확인하세요.
3. 지도를 고르고 탐험, 사건 선택, 대화 기록 재생, 투표 확정을 진행하며 읽기 속도와 버튼 위치가 편한지 확인하세요.
4. 실제 사용하는 모바일 기기와 브라우저에서 글씨 크기·터치·음원 자동 재생 정책을 확인하세요. `file://` 실행보다 로컬 미리보기 주소가 일관된 저장 공간을 제공합니다.

이 확인은 아직 수행하지 않은 주관적/실기기 평가이며 자동 테스트를 사용자에게 떠넘기는 의미가 아닙니다. 위 코드·기능 검증은 이미 수행했습니다.

## 12. PHASE 6 진입 가능 여부

**Phase 6 개발 기반으로 진입 가능합니다.** 실제 에셋을 연결한 시각·음향·설정과 기존 게임의 회귀 및 브라우저 흐름 검증을 마쳤습니다. 상용 출시 품질과 장시간 음향·기기 성능 평가까지 완료했다는 의미는 아닙니다. Phase 6의 AI 난이도·밸런스 고도화는 이번 작업에서 시작하지 않았습니다.
