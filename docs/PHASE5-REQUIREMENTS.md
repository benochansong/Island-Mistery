# ISLAND MYSTERY
## DEVELOPMENT PHASE 5 — CINEMATIC VISUAL & AUDIO EXPERIENCE
### 캐릭터 디자인 · 섬 지도 · UI/UX · 애니메이션 · 배경음악 · 효과음 · 게임 연출

당신은 ISLAND MYSTERY 프로젝트의 수석 게임 아트 디렉터, 프런트엔드 게임 개발자, UI/UX 디자이너, 애니메이션 개발자, 사운드 디자이너이자 QA 엔지니어입니다.

지금부터 PHASE 1~4에서 개발한 ISLAND MYSTERY 프로젝트를 기반으로 PHASE 5를 진행합니다.

이번 개발의 핵심 목표는 **기존 게임 시스템을 유지하면서 플레이어가 실제 상용 2D 미스터리 어드벤처 게임을 즐기는 것처럼 느낄 수 있는 시각적·청각적 경험을 완성하는 것**입니다.

단순한 디자인 시안이나 정적인 이미지 제작이 아닙니다.

실제 게임 데이터와 연결되는 그래픽, UI, 애니메이션 및 사운드 시스템을 구현해야 합니다.

# PART 2. 게임 아트 방향 설정

## STEP 2 — 통일된 비주얼 스타일

ISLAND MYSTERY의 그래픽 스타일은 다음과 같이 설정합니다.

**아트 콘셉트: Cinematic Tropical Mystery Adventure**

핵심 분위기:

- 열대 무인도의 아름다움과 불안감
- 짙은 정글과 신비로운 자연
- 오래된 연구시설의 불길한 분위기
- 생존자 사이에 흐르는 긴장감
- 탐험과 발견의 즐거움
- 밤이 되면 더욱 깊어지는 미스터리

시각적 방향:

- 고품질 2D 일러스트 기반
- 세미 리얼리스틱 캐릭터
- 통일된 영화적 색감
- 은은한 조명과 그림자
- 레이어 기반 패럴랙스 효과
- 부드러운 화면 전환
- 과도하지 않은 시각 효과

전체 그래픽의 일관성을 최우선으로 합니다.

웹게임이므로 처음부터 3D 엔진을 도입하지 마세요.

HTML5, CSS3, JavaScript, Canvas 또는 SVG를 활용합니다.

기존 프로젝트의 기술 구조를 우선 유지하세요.

# PART 3. 메인 타이틀 화면

## STEP 3 — 고급 메인 화면 구현

게임의 첫 화면을 영화적인 분위기로 개선합니다.

화면 구성:

- ISLAND MYSTERY 로고
- 부제: 사라진 섬의 비밀
- 열대 무인도 배경
- 바다와 정글
- 멀리 보이는 버려진 연구시설
- 움직이는 구름과 안개
- 은은한 배경음악

메인 메뉴:

- 새 게임
- 이어하기
- 미스터리 도감
- 설정
- 게임 소개

버튼에 마우스를 올리면 자연스러운 반응이 나타나도록 합니다.

게임 시작 시 짧은 화면 전환 연출을 제공합니다.

실제 게임 진행 기능과 모든 버튼을 연결하세요.

기존 저장 데이터가 없다면 이어하기 버튼을 비활성화합니다.

# PART 4. 섬 지도 그래픽

## STEP 4 — 인터랙티브 섬 지도

기존 탐험 지도 UI를 개선합니다.

섬 전체를 보여주는 2D 지도를 제작합니다.

핵심 지역:

1. 해안가 — 푸른 바다, 난파선, 모래사장
2. 정글 — 울창한 열대 수목, 오래된 유적
3. 연구소 — 버려진 건물, 폐쇄된 실험시설
4. 통신탑 — 산악 지형, 철제 통신시설

숨겨진 장소:

5. 연구소 지하실
6. 정글 관측소
7. 해안가 비밀 동굴
8. 통신탑 지하 장비실

각 지역에 상호작용 가능한 아이콘을 배치합니다.

지도 기능:

- 지역 선택
- 선택 지역 강조
- 지역 상세 정보 표시
- 위험 수준 표시
- 획득 가능한 자원 정보
- 발견한 단서 표시
- 잠긴 장소와 열린 장소 구분
- 탐험 완료 표시

잠긴 지역의 실제 비밀 정보는 미리 공개하지 않습니다.

지역에 마우스를 올리면 간략한 설명이 나타납니다.

지역을 클릭하면 기존 탐험 시스템이 실행 가능한 상태로 연결됩니다.

지도는 화면 크기에 맞게 조정되어야 합니다.

# PART 5. 캐릭터 비주얼 시스템

## STEP 5 — 6인 캐릭터 초상화

인간 플레이어 1명과 AI 5명을 위한 캐릭터 디자인을 구현합니다.

캐릭터들은 서로 구별 가능한 외모, 복장, 표정, 실루엣을 가져야 합니다.

캐릭터 디자인 방향:

- 현실적인 생존자 복장
- 열대 무인도 환경에 어울리는 의상
- 개성 있는 헤어스타일
- 성격을 보여주는 표정
- 통일된 일러스트 스타일

필요한 캐릭터 상태:

- 기본 표정
- 의심하는 표정
- 화난 표정
- 불안한 표정
- 놀란 표정
- 부상 상태

캐릭터 이미지가 존재하는 경우 실제 UI에 연결하세요.

이미지 제작 기능을 사용할 수 없다면 고품질 CSS/SVG 기반 임시 초상화와 정확한 이미지 제작 명세를 준비하세요.

이미지를 생성하지 않았으면서 생성했다고 보고하지 마세요.

캐릭터 이미지에는 고정된 직업 표시를 넣지 마세요.

같은 캐릭터가 다음 게임에서는 다른 직업을 맡을 수 있어야 합니다.

특히 공작원의 정체가 외모나 이미지 때문에 드러나지 않도록 합니다.

# PART 6. 캐릭터 애니메이션

## STEP 6 — 기본 캐릭터 모션

복잡한 전신 애니메이션보다 게임에 필요한 미세한 움직임부터 구현합니다.

필수 애니메이션:

- 캐릭터 등장
- 발언 시 강조
- 선택 시 반응
- 의심 대상 지정
- 투표 결과 발표
- 부상 효과
- 탈락 및 추방 효과
- 엔딩 등장 연출

대화 중인 캐릭터는 화면에서 자연스럽게 강조합니다.

캐릭터 표정 또는 초상화 효과가 대화 내용과 연결되도록 합니다.

애니메이션은 게임 진행을 방해하지 않아야 합니다.

건너뛰기 및 효과 감소 옵션을 제공합니다.

# PART 7. 낮과 밤의 시각적 변화

## STEP 7 — 시간대별 환경 연출

게임 진행 단계에 따라 화면의 분위기를 변경합니다.

### MORNING — 아침

- 밝은 햇빛
- 새소리
- 잔잔한 바다
- 탐험 시작 분위기

### AFTERNOON — 낮

- 강한 태양
- 활발한 자연 환경
- 탐험 및 임무 수행 효과

### DISCUSSION — 저녁

- 붉은 노을
- 모닥불
- 캐릭터들이 모인 장면
- 긴장감을 높이는 조명

### VOTING — 투표

- 어두워지는 배경
- 긴장감 있는 음악
- 투표함과 후보 선택 효과
- 결과 발표 연출

### NIGHT — 밤

- 어두운 정글
- 달빛
- 안개
- 제한된 시야
- 위험하고 불길한 분위기

기존 게임 시간대 상태와 시각 효과를 연결합니다.

날짜와 시간이 바뀌면 화면도 자동으로 변화하도록 합니다.

# PART 8. 탐험 연출

## STEP 8 — 탐험 결과 애니메이션

플레이어가 지역을 탐험하면 시각적인 반응이 나타나야 합니다.

필수 연출:

- 탐험 시작
- 지역 이동
- 탐색 진행
- 자원 발견
- 단서 발견
- 부상
- 탐험 실패
- 비밀 장소 발견

예시:

플레이어가 정글을 선택합니다.

탐험 시작 버튼을 누르면 정글 화면으로 전환됩니다.

탐색 애니메이션이 나타납니다.

탐험 결과가 공개됩니다.

식량 2개를 얻었다면 식량 아이콘과 수치 증가 효과를 표시합니다.

중요한 단서를 발견했다면 일반 자원 발견보다 특별한 연출을 사용합니다.

실제 결과는 기존 게임 로직에서 결정해야 합니다.

애니메이션이 자원 수량이나 사건 결과를 다시 계산해서는 안 됩니다.

# PART 9. 토론 및 심리전 화면

## STEP 9 — 시네마틱 토론 UI

PHASE 3에서 구현한 AI 토론 시스템의 화면을 개선합니다.

화면 구성:

- 토론 장소 배경
- 참여 캐릭터 초상화
- 현재 발언자 강조
- 캐릭터 이름
- 대화 텍스트
- 인간 플레이어의 응답 선택지
- 주요 증거 표시
- 토론 진행 상태

발언 내용을 읽기 쉽도록 대화창을 구성합니다.

캐릭터별 발언 스타일은 통일하되 표정과 시각적 반응에 차이를 둡니다.

AI가 서로 반박할 때는 반응 효과를 제공합니다.

중요한 증거가 공개될 때는 별도의 강조 연출을 사용합니다.

단순히 대화를 화려하게 보여주는 것뿐 아니라, 사용자가 사건 흐름을 이해하기 쉽도록 개선하세요.

대화 기록을 다시 볼 수 있어야 합니다.

토론을 빠르게 진행하거나 연출을 건너뛸 수 있는 옵션을 구현합니다.

# PART 10. 투표 화면 개선

## STEP 10 — 긴장감 있는 투표 시스템

기존 투표 기능을 시각적으로 개선합니다.

요구사항:

- 투표 가능한 생존자 표시
- 후보자 선택 시 강조 효과
- 투표 확정 버튼
- AI 투표 진행 표시
- 투표 결과 공개 애니메이션
- 최다 득표자 강조
- 추방 결과 연출

투표 결과 발표 시 긴장감을 줄 수 있는 효과를 사용합니다.

단, 실제 투표 결과는 기존 게임 로직에서 결정합니다.

애니메이션 도중 투표가 두 번 집계되지 않아야 합니다.

추방된 인물의 상태는 게임 전체 UI에 즉시 반영합니다.

인간 플레이어가 추방되면 기존 관전 기능과 연결하세요.

# PART 11. 랜덤 사건 연출

## STEP 11 — 사건 유형별 시각 효과

PHASE 4에서 구현한 36개 랜덤 사건을 시각적으로 표현합니다.

사건 유형별 연출:

- 폭풍: 화면 흔들림, 비와 번개
- 시설 파괴: 경고등, 전기 스파크
- 비밀 문서 발견: 문서 확대 화면
- 식량 실종: 자원 감소 효과
- 부상: 경고 아이콘
- 무전 수신: 신호 그래픽
- 비밀 장소 발견: 지도 잠금 해제
- 중요한 증언: 대화 강조

모든 사건에 별도의 복잡한 애니메이션을 제작할 필요는 없습니다.

공통 효과를 재사용하도록 설계합니다.

사건 화면에서는 다음 정보를 제공하세요.

- 사건 이름
- 사건 설명
- 관련 장소
- 플레이어 선택지
- 선택 결과
- 자원 또는 관계 변화

공작원의 비밀 행동은 공개 가능한 정보만 보여줘야 합니다.

# PART 12. 배경음악 시스템

## STEP 12 — BGM 관리 엔진

게임 상황별 배경음악 시스템을 구현합니다.

음악 분위기:

1. 메인 메뉴 — 신비로운 섬
2. 아침 탐험 — 호기심과 모험
3. 낮 임무 — 긴장과 집중
4. 저녁 토론 — 불안한 심리전
5. 투표 — 고조되는 긴장감
6. 밤 — 공포와 미스터리
7. 생존자 승리 — 희망적인 분위기
8. 공작원 승리 — 어둡고 불길한 분위기
9. 생존 실패 — 비극적인 분위기

실제 음악 파일을 제작할 수 있는 도구가 있다면 독창적인 음악을 제작하거나 사용 권한이 확인된 음악을 사용하세요.

음악 파일이 준비되지 않았다면 음향 관리 시스템과 파일 연결 구조를 먼저 완성하고, 필요한 음악의 제작 명세를 별도로 작성하세요.

음악 파일이 없는데 재생되는 것처럼 구현하거나 보고하지 마세요.

사운드 시스템 요구사항:

- 배경음악 켜기/끄기
- 음악 볼륨 조절
- 효과음 볼륨 조절
- 단계별 음악 변경
- 음악 페이드 인/아웃
- 설정 저장

브라우저의 자동 재생 제한을 준수하고, 사용자의 첫 상호작용 이후 오디오를 시작하도록 구현하세요.

# PART 13. 게임 효과음

## STEP 13 — SFX 구현

다음 상황에서 효과음이 재생되도록 구현합니다.

- 버튼 클릭
- 지도 지역 선택
- 탐험 시작
- 자원 획득
- 단서 발견
- 위험 경고
- 비밀 장소 발견
- 대화 전환
- 중요한 증언
- 투표 확정
- 투표 결과
- 추방
- 시설 수리
- 시설 파괴
- 게임 승리
- 게임 패배

효과음이 지나치게 반복되거나 겹치지 않도록 제어합니다.

볼륨을 적절하게 조절하고 효과음 중복 재생을 방지하세요.

저작권 및 사용 권한이 확인되지 않은 음원은 프로젝트에 포함하지 마세요.

# PART 14. UI/UX 완성도 향상

## STEP 14 — 사용하기 편리한 게임 화면

전체 UI를 일관된 디자인 시스템으로 통합합니다.

주요 구성:

- 상단: 날짜, 시간, 게임 단계
- 측면: 생존자 상태
- 자원 패널: 식량, 식수, 의약품, 부품
- 중앙: 지도 또는 현재 게임 화면
- 하단: 선택지 및 실행 버튼
- 보조 메뉴: 사건 기록, 단서, 관계, 설정

사용자가 현재 무엇을 해야 하는지 명확하게 표시하세요.

게임 진행에 필수적인 버튼은 쉽게 찾을 수 있어야 합니다.

각 버튼에 마우스를 올리면 용도를 확인할 수 있도록 합니다.

PC 환경을 우선 지원하고, 태블릿과 모바일 화면에서도 레이아웃이 깨지지 않도록 개선합니다.

단축키는 필수 기능이 정상 구현된 뒤 추가합니다.

가독성과 사용성을 해치는 지나친 시각 효과는 피하세요.

# PART 15. 접근성과 편의 기능

## STEP 15 — 게임 설정 확장

다음 옵션을 구현합니다.

- 음악 켜기/끄기
- 효과음 켜기/끄기
- 전체 볼륨 조절
- 애니메이션 효과 감소
- 화면 흔들림 끄기
- 텍스트 표시 속도 조절
- 대화 자동 진행 켜기/끄기
- 대화 건너뛰기
- 전체화면 전환
- 설정 초기화

설정은 localStorage에 저장합니다.

전체화면 기능이 지원되지 않는 환경에서는 오류 없이 일반 화면으로 유지되도록 합니다.

색상만으로 중요한 게임 정보를 구분하지 않도록 합니다.

작은 글씨 때문에 게임을 진행하기 어려운 상황을 방지하세요.

# PART 16. 이미지 및 리소스 관리

## STEP 16 — 에셋 관리 시스템

이미지, 음악, 효과음 등을 체계적으로 관리합니다.

예시:

assets/
- images/
- characters/
- backgrounds/
- maps/
- ui/
- audio/
- effects/

현재 프로젝트 구조에 맞게 실제 폴더를 구성하세요.

필수 조건:

- 이미지 로딩 실패 시 대체 화면 표시
- 사운드 파일이 없더라도 게임 실행 가능
- 사용하지 않는 리소스 정리
- 이미지 파일 크기 최적화
- 로딩 상태 표시
- 파일 경로 관리 일원화

이미지 제작 기능이 없다면 필요한 에셋 목록과 제작 프롬프트를 별도 문서로 정리하세요.

모든 그래픽과 사운드에는 제작 출처 및 이용 권한을 확인할 수 있는 정보를 기록하세요.

# PART 17. 게임 성능 최적화

## STEP 17 — 웹게임 성능 개선

일반적인 노트북과 데스크톱에서 원활하게 실행되도록 최적화합니다.

다음 문제를 점검하세요.

- 불필요한 애니메이션 반복
- 과도한 DOM 업데이트
- 메모리 누수
- 중복 이벤트 리스너
- 이미지 로딩 지연
- 사운드 중복 재생
- 저장 데이터 충돌
- 브라우저 화면 멈춤

애니메이션은 가능한 경우 requestAnimationFrame 또는 CSS 애니메이션을 사용하세요.

화면이 보이지 않는 상태에서 불필요한 렌더링을 줄이세요.

애니메이션을 꺼도 게임의 핵심 기능은 정상 작동해야 합니다.

# PART 19. 필수 테스트

## STEP 19 — 실제 플레이 검증

다음 항목을 반드시 테스트하세요.

### 그래픽 테스트

- 메인 화면이 정상적으로 표시되는가
- 섬 지도의 지역을 클릭할 수 있는가
- 캐릭터 정보가 정상 표시되는가
- 날짜별 배경 변화가 이루어지는가
- 숨겨진 장소가 적절하게 표시되는가
- 이미지 로딩 실패 시 게임이 멈추지 않는가

### 애니메이션 테스트

- 탐험 결과와 애니메이션이 일치하는가
- 투표 애니메이션이 중복 투표를 발생시키지 않는가
- 추방 이후 캐릭터 상태가 정상 변경되는가
- 화면 효과를 꺼도 게임을 진행할 수 있는가
- 대화 건너뛰기가 정상 작동하는가

### 사운드 테스트

- 배경음악이 정상 재생되는가
- 단계별 음악 변경이 작동하는가
- 효과음 중복 재생이 제어되는가
- 볼륨 설정이 저장되는가
- 음원 파일이 없을 때 게임이 정상 작동하는가

### 전체 게임 테스트

- 게임 시작부터 엔딩까지 진행
- AI 5명 정상 행동
- 3일간 게임 진행
- 랜덤 사건 발생
- 토론 및 투표
- 공작원 행동
- 저장 및 이어하기
- 엔딩 및 도감
- 화면 전환 중 오류 없음

가능하면 Chromium 기반 브라우저와 Firefox에서 주요 화면을 확인하세요.

서로 다른 난수 시드로 최소 100회 게임 로직 자동 시뮬레이션을 수행하세요.

실제 브라우저 UI 테스트는 자동 시뮬레이션과 별개로 수행하세요.

이전 PHASE 4에서 정상 작동하던 기능이 새 그래픽 때문에 중단되지 않는지 회귀 테스트를 수행합니다.

실제로 수행하지 않은 테스트는 완료했다고 보고하지 마세요.
