# Phase 7 온라인 멀티플레이 재검증·보완 완료

2026-11-20. 재전달된 요구사항을 현재 Phase 8 코드에 적용했다. **기존 싱글플레이·성장·업적·SQLite 전적을 보존하면서 온라인 대기실의 진행 방해 경로를 수정하고 실제 서버/브라우저로 재검증했다.** 공개 인터넷 배포를 완료했다는 의미는 아니다.

## 1. 기존 Phase 6 및 현재 상태

[시작 진단](PHASE7-REPAIR-BASELINE.md)에 요청한 기존 기능 15개와 PASS/PARTIAL/FAIL/MISSING 판정을 기록했다. 핵심 규칙은 동작했으며 AI의 실제 인간 경쟁 밸런스는 PARTIAL이다. 현재는 Phase 8까지 구현되어 있어 과거 Phase 6 버전으로 되돌리지 않았다. 변경 전 전체 소스는 Git 커밋 `39ad3056b30d3f7e087cb5f1b201f68aef91ec51`로 보존했다.

## 2. 이번 구현·수정

- **시작 불가능한 방 방지:** AI 비허용이면 최대 인원을 6명으로 고정하고 서버도 모순된 설정을 거부한다. AI 비허용 대기실의 AI 인원은 0명으로 표시한다.
- **대기실 좌석 정리:** 연결이 끊기면 기본 120초 복귀를 기다린다. 기한 후 좌석을 해제해 남은 참가자가 새 친구와 시작할 수 있다. `LOBBY_RECONNECT_MS`로 설정하며 청소 주기 외에 참가·복귀·시작 시에도 확인한다.
- **진행 중 게임 보호:** 대기실 만료 규칙을 진행 중 게임에 적용하지 않는다. 기존 캐릭터·직업과 제출 상태를 유지하고 단계 제한 시간으로 게임을 진행한다.
- **실패 복구:** 복귀 기한이 지난 브라우저의 잘못된 방 토큰을 제거하고 생성/참가 폼을 다시 표시한다. 영구 게스트 프로필 토큰은 지우지 않는다.
- **생성 실패 정리:** 프로필 처리 중 오류가 생기면 막 생성한 빈 방을 제거한다.

새 소켓 테스트는 수정 전 3개 중 2개 실패, 수정 후 모두 통과했다. 대기실 프로필 쓰기 실패는 의도적으로 주입한 오류 테스트이며 정상 운영에서 DB 장애가 발생했다는 뜻은 아니다.

## 3. 서버와 클라이언트 구조

기존 HTML/CSS/JS 화면 → Socket.IO 요청 → `server/rooms.cjs`의 인증·단계·행동 검사 → 공용 게임 엔진 → 참가자별 공개 범위 snapshot → 각 브라우저 렌더링 구조다. 서버가 직업·비밀 목표·AI 기억·투표 대기열·자원·날짜·승패를 관리한다. 클라이언트는 행동 의도를 보내며 수치나 승리 결과를 직접 쓸 수 없다.

진행 중 방은 단일 서버 메모리에 있다. 완료한 전적·XP·업적은 기존 Phase 8 SQLite 트랜잭션으로 보존한다. 오프라인 저장, 방 재접속 토큰, 영구 게스트 토큰은 서로 분리한다. 브라우저 UI → 서버 규칙 → DB 정산 → 개인 응답 → 기록 화면까지 `vercel:verification` 절차로 검증했다.

## 7. 인간·AI 혼합 검증

2~6개의 독립 Socket.IO 연결과 AI 4~0명 구성을 실제 서버에서 각각 엔딩까지 진행했다. 자동 클라이언트 검증이며 사람 여섯 명이 직접 조작했다는 뜻은 아니다. AI를 끈 방은 실제 참가자 6명일 때만 시작한다.

AI 공작원·인간 공작원 모두 서버 내부에서 해당 자연 초기 배정을 선택한 조건부 테스트로 완주했다. 공개 API에서 직업을 주입하지 않는다. 이번 브라우저 자연 2판은 인간 역할이 의사/기술자와 의사/의사로, **모두 AI 공작원**이었다. 인간 공작원은 이번 온라인 소켓 조건부 완주와 이전 [Phase 8 브라우저 실제 실행](phase8-online-browser-results.json)에서 확인한 사례를 구분한다.

## 8. 비밀 정보·중복·입력 보호

온라인 응답에 타인 직업·개인 단서·AI 기억, 전체 `secrets`/`facts`, 난수 시드, 재접속 토큰 해시를 넣지 않는 검사를 통과했다. 투표는 집계 전 대상 비공개이며 관전자는 행동과 생존자 채팅을 제출할 수 없다. 단서 소유자 전용 sentinel 검사, 역할 위조·자원 주입·잘못된 단계·중복 요청 거부도 유지된다.

HTML 문자열 채팅이 상대 브라우저에 문자로 표시되고 이미지/스크립트로 실행되지 않았다. 채팅 길이·빈도, 패킷 크기, 연결 수, 다른 Origin, 비공개 파일 HTTP 접근 거부를 검사했다. 이는 해당 공격 사례의 회귀이며 독립 침투 테스트를 뜻하지 않는다.

## 9. 연결·재접속 검증

새로고침 복귀, 실제 브라우저 네트워크 차단 후 복귀, 창 종료 후 같은 저장소 복귀를 수행했다. 닉네임만으로 좌석을 가져오거나 잘못된 토큰으로 복귀할 수 없다. 유예가 지난 대기실 토큰은 실패하고 생성/참가 화면이 다시 열린다. 게임 시작 후에는 유예보다 오래 닫았다 돌아와도 같은 직업을 유지한다.

온라인 연결 실패 후 오프라인 이어하기가 가능하며 기존 저장 원문이 바뀌지 않는 것도 확인했다. [연결 기능 결과](phase7-repair-features-browser-features.json), [네트워크 차단 화면](phase7-repair-features-disconnected.png).

**한 PC에서 실제 Chrome와 Firefox 간 통신을 검증했다. 두 물리 기기·외부 인터넷 회선·실제 휴대폰 테스트는 수행하지 않았다.**

## 11. 남은 제한

이번 필수 로컬 흐름에서 재현된 진행 중단 문제는 수정했다. 다음은 완료로 보고하지 않는다.

- 공개 서버·TLS 프록시·실제 두 기기·장시간 부하/지연·패킷 손실 검증.
- 진행 중 방의 서버 재시작 복원과 다중 서버 공유 상태. 완료 전적은 SQLite에 보존하지만 진행 방은 소멸한다.
- 영구 계정/토큰 분실 복구·글로벌 랭킹. 현재는 로컬 게스트 기록이며 글로벌은 비활성이다.
- 자유 채팅의 의미 분석, 자동 신고 제재, 음성 채팅, 이탈자의 즉시 AI 교체.
- 인간 여러 명의 경쟁 밸런스. Phase 8 자동 표본의 생존자 우세를 이번 네트워크 수정으로 해결했다고 주장하지 않는다.

## 12. Windows 실행

Node.js **22.13 이상(24 권장)** 설치 → `start-online.cmd` 더블클릭 → 출력된 주소 접속 → 온라인 멀티플레이 → 방 생성/참가 → 모두 준비 → 방장 시작. 같은 PC에서는 독립 브라우저/시크릿 저장소를 사용한다. 종료는 서버 창 Ctrl+C. HTML 파일만 열어서는 온라인 기능이 작동하지 않는다.

설치·친구 초대·LAN·오류 해결·대기실 유예 설정은 [실행 설명서](PHASE7-RUN.md), 완료 전적 및 DB 백업은 [Phase 8 안내](PHASE8-RUN.md)에 있다.

## 13. 인터넷 공개 배포 준비

지속 실행 Node.js 호스트, HTTPS와 보안 WebSocket 프록시, `APP_ORIGIN`/`APP_DOMAIN` 환경 설정, 운영 백업·접속 제한·모니터링과 실제 외부 회선 검증이 필요하다. 소스에 운영 도메인을 하드코딩하지 않았으며 DNS·인증서·공개 라우팅은 변경하지 않았다. 로컬 초대 주소는 공개 인터넷 초대 URL이 아니다.

## 14. Phase 8 상태

Phase 8은 이미 구현되어 있으며 이번 보완에서 유지했다. 성장·30개 업적·보상·6개 도전·48개 사건·SQLite 전적 회귀가 통과했다. 온라인 완주 후 두 브라우저의 서버 프로필/랭킹 일치도 재확인했다. 이번 요청을 과거 단계로의 롤백이나 외부 배포 승인으로 해석하지 않았다.
