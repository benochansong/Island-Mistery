# ISLAND MYSTERY
## DEVELOPMENT PHASE 9 — BETA TESTING, GAME POLISH & RELEASE READINESS
### 베타 테스트 · 게임 완성도 · 사용자 경험 · 오류 수정 · 보안 점검 · 출시 준비

당신은 ISLAND MYSTERY 프로젝트의 총괄 게임 디렉터, 시니어 게임 개발자, QA 엔지니어, UX 전문가, 온라인 게임 서버 엔지니어 및 출시 품질 관리 책임자입니다.

지금부터 기존 PHASE 1~8에서 개발한 ISLAND MYSTERY 프로젝트를 기반으로 DEVELOPMENT PHASE 9를 진행합니다.

이번 단계의 핵심 목표는 **실제 사용자들이 게임을 처음부터 끝까지 즐길 수 있도록 게임 전체를 검증하고, 발견된 문제를 해결하여 베타 테스트가 가능한 안정적인 버전을 완성하는 것**입니다.

중요한 점은 새로운 기능을 추가하는 것이 아닙니다.

이미 개발된 기능이 정상적으로 작동하는지 검증하고, 게임의 재미와 편의성을 개선하며, 실제 배포를 준비하는 것이 이번 단계의 목적입니다.

# PART 2. 베타 테스트 버전 준비

## STEP 2 — 안정적인 베타 버전 구성

현재 게임을 베타 테스트용 버전으로 정리합니다.

버전 이름:

ISLAND MYSTERY — BETA 0.9.0

버전 번호는 현재 프로젝트에 이미 존재하는 버전 관리 체계가 있으면 그 기준을 따르세요.

개발 환경과 베타 테스트 환경을 분리합니다.

베타 환경에서는 다음 조건을 충족해야 합니다.

- 게임이 정상 실행됨
- 개발용 테스트 데이터가 실제 데이터와 구분됨
- 개발자 디버그 메뉴가 일반 사용자에게 노출되지 않음
- 공개되지 않은 직업 정보가 노출되지 않음
- 테스트 중 발생한 오류를 확인할 수 있음
- 문제가 발생하면 이전 안정 버전으로 복원할 수 있음

베타 버전이라는 이유로 기존 싱글플레이 데이터를 삭제하지 마세요.

실제 외부 서버 배포나 공개 테스트 시작은 사용자의 명시적 승인을 받은 뒤 진행합니다.

이번 단계에서는 먼저 로컬 또는 접근이 제한된 테스트 환경에서 검증하세요.

# PART 3. 싱글플레이 전체 테스트

## STEP 3 — 게임 처음부터 엔딩까지 검증

싱글플레이를 실제로 실행하여 다음 과정을 확인하세요.

게임 시작 → 직업 배정 → 탐험 → 자원 획득 → 비밀 임무 → AI 토론 → 투표 → 밤 행동 → 다음 날 → 최종 엔딩

검증할 상황:

### 시나리오 A — 일반 생존자

인간 플레이어가 생존자로 시작하여 탐험과 추리를 진행합니다.

### 시나리오 B — 인간 공작원

인간 플레이어가 공작원으로 시작하여 시설 파괴와 거짓말을 사용합니다.

### 시나리오 C — AI 공작원

AI가 공작원으로 배정되어 위장과 방해 행동을 수행합니다.

### 시나리오 D — 인간 플레이어 추방

인간 플레이어가 추방된 뒤 관전 모드로 전환됩니다.

### 시나리오 E — 생존 실패

자원이 부족하거나 생존 조건을 충족하지 못하여 게임이 종료됩니다.

### 시나리오 F — 특별 엔딩

주요 단서와 숨겨진 장소를 발견하여 특별한 엔딩을 확인합니다.

각 시나리오에서 버튼, 화면 전환, 자원 계산, AI 행동, 승패 판정을 확인하세요.

# PART 5. 네트워크 장애 및 예외 처리

## STEP 5 — 비정상 상황 대응

실제 온라인 게임에서는 네트워크 문제가 발생할 수 있습니다.

다음 상황을 재현하세요.

- 참가자 새로고침
- 일시적인 연결 끊김
- 게임 중도 이탈
- 방장 이탈
- 투표 도중 연결 종료
- 밤 행동 도중 연결 종료
- 서버 응답 지연
- 동일 행동 중복 전송
- 잘못된 방 코드 입력
- 이미 종료된 게임방 참가
- 재접속 시 기존 캐릭터 복원

동일 플레이어의 행동이 두 번 실행되지 않도록 합니다.

연결이 끊겨도 다른 플레이어들의 게임이 무한정 중단되지 않아야 합니다.

재접속한 플레이어는 기존 직업과 상태를 유지해야 합니다.

재접속 토큰과 비밀 정보는 다른 사용자에게 노출되지 않아야 합니다.

# PART 6. AI 행동 품질 검증

## STEP 6 — AI 캐릭터의 판단 평가

PHASE 3과 PHASE 6에서 개발한 AI 시스템을 실제로 분석하세요.

검증할 항목:

- 캐릭터마다 다른 성격이 표현되는가
- 과거 사건을 기억하는가
- 발견한 단서를 올바르게 활용하는가
- 근거 없이 다른 사람을 의심하지 않는가
- 거짓말을 유지하거나 수정할 수 있는가
- 새로운 증거를 보고 판단을 바꾸는가
- 공작원이 전략적으로 행동하는가
- AI들이 무조건 같은 대상에게 투표하지 않는가
- 인간 플레이어의 행동에 반응하는가
- 비밀 정보를 부당하게 참조하지 않는가

특히 AI의 대화가 단순히 길기만 하고 내용이 없는 문제를 개선하세요.

토론은 다음 구조를 유지해야 합니다.

사건 공유 → 의심 제기 → 질문과 해명 → 증거 검토 → 최종 의견

AI의 발언에는 실제 사건이나 캐릭터의 믿음이 반영되어야 합니다.

다른 캐릭터가 의도적으로 거짓말하는 상황과 시스템이 존재하지 않는 사실을 잘못 생성하는 상황을 구분하세요.

플레이어의 선택과 전략이 결과에 영향을 줄 수 있어야 합니다.

# PART 8. 대규모 자동 테스트

## STEP 8 — 반복 시뮬레이션

기존 자동 테스트 시스템을 활용하여 최소 1,000회의 게임 로직 시뮬레이션을 수행하세요.

권장 구성:

- EASY 200회
- NORMAL 400회
- HARD 200회
- 특별 도전 모드 200회

인간 플레이어의 행동은 문서화된 자동 플레이 정책으로 대체합니다.

AI 공작원과 인간 공작원 시뮬레이션이 모두 포함되도록 구성하세요.

모든 게임에는 재현 가능한 난수 시드를 사용합니다.

기록할 항목:

- 총 실행 횟수
- 정상 종료 횟수
- 비정상 종료 횟수
- 단계 진행 오류
- AI 행동 오류
- 승패 판정 오류
- 저장 데이터 오류
- 자원 중복 계산
- 투표 중복 집계
- 정보 접근 위반
- 진영별 승률
- 평균 게임 종료 날짜
- 주요 사건별 발생 빈도

실패한 시드와 실행 로그를 저장하여 오류를 재현할 수 있도록 합니다.

오류를 수정한 후 해당 시드를 다시 실행하세요.

1,000회 시뮬레이션은 게임 로직 검증이며, 실제 사람이 게임을 즐기는 테스트를 대신할 수 없습니다.

실행 환경의 제약으로 목표 횟수를 수행하지 못하면 실제 실행 횟수와 그 이유를 보고하세요.

# PART 9. 사용자 경험 개선

## STEP 9 — 처음 접하는 플레이어 관점에서 점검

게임 개발 경험이 없는 일반 사용자가 처음 접속했다고 가정하고 UI를 분석하세요.

다음 질문을 기준으로 평가합니다.

- 게임 시작 버튼을 쉽게 찾을 수 있는가
- 게임의 목표를 이해할 수 있는가
- 자신의 직업과 능력을 확인할 수 있는가
- 탐험 방법이 명확한가
- 자원 현황을 쉽게 파악할 수 있는가
- 토론 중 무엇을 해야 하는지 알 수 있는가
- 투표 방법이 직관적인가
- 다음 단계로 넘어가는 방법이 명확한가
- 엔딩에서 승패의 이유를 이해할 수 있는가

문제가 있는 경우 UI를 개선합니다.

모든 버튼은 실제 기능과 연결되어야 합니다.

사용자가 게임 도중 다음에 무엇을 해야 할지 몰라서 진행을 멈추지 않도록 안내 기능을 보완하세요.

# PART 11. 실제 사용자 베타 테스트 준비

## STEP 11 — 외부 테스트 운영 기능

실제 사람들의 플레이 결과를 바탕으로 게임을 개선할 수 있도록 베타 테스트용 기능을 구현합니다.

다음 기능을 준비하세요.

- 베타 버전 표시
- 게임 플레이 후 의견 남기기
- 버그 신고
- 개선 제안
- 게임 만족도 평가
- 오류 재현 정보 기록
- 피드백 확인 및 분류

실제 외부 테스터를 초대하거나 공개 배포하는 행위는 사용자의 승인을 받은 후 진행합니다.

개인정보나 플레이 로그를 수집하는 경우 수집 목적, 항목, 보관 기준을 명확하게 안내하고 필요한 동의를 받아야 합니다.

계정 비밀번호, 인증 토큰, 비공개 채팅 내용, 다른 플레이어의 비밀 역할 정보를 오류 보고서에 자동 포함하지 마세요.

외부 수집 서버가 아직 없다면 로컬에서 저장하거나 사용자가 직접 제출할 수 있는 피드백 양식을 먼저 구현합니다.

### P1 — 주요 오류

문구, 정렬, 사소한 시각 효과 문제 등
